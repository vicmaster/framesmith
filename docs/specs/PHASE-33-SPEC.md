## 1. SPECIFY

### Problem

Phase 31 rebuilt the viewer as canvases to prove the desktop-app rules, and left the code port out of scope (PHASE-31-SPEC, "No code port of the viewer"). Those canvases proved the gates, not the look: empty grey thumbnails, the accent on every title and link, a bare list of category numbers, and a filled Delete button as the loudest thing on the detail page. The 2026-11-24 design pass replaced them with seven screens that keep the gates and fix the look. The viewer itself is unchanged since Phase 30 and has problems of its own:

1. **It looks like neither design.** `src/viewer.ts` (1,943 lines) renders three pages as template strings with one dark-only theme (`THEME_CSS`, `viewer.ts:306-343`, no `prefers-color-scheme`). Scores are coloured green, amber or red at 80 and 60 (`scoreColor`, `viewer.ts:933`), a scale unrelated to the bar the evaluator holds designs to (more than 95).
2. **"Live" is only half true.** The project page polls `/api/canvases` every 3 seconds and reloads only when the canvas count changes (`viewer.ts:687-697`), so an edited design keeps its old thumbnail. The detail page refreshes its preview on change (`viewer.ts:1509-1529`) but never the Quality, Design system or Feedback panes, so a comment the agent resolved stays open until a manual reload.
3. **Parts of it cannot be reached by keyboard or touch.** Inspector tabs are `<span>`s (`viewer.ts:1117`), and the archive's Restore and Delete appear on hover only (`.card-actions`, opacity 0 until hover).
4. **Small defects.** The archive card shows `lastModified` as its archived date (`viewer.ts:719`); archiving sets both to the same time (`scene-graph.ts:343-344`), so the date goes wrong only after a later edit, but `archivedAt` is the field that means it; the project page inlines `projectId` into a script unescaped (`viewer.ts:693`); the Import tab has been a disabled "Coming in Phase 19 Slice C" placeholder for fourteen phases (`viewer.ts:1120`); README says `/` is the gallery (it redirects to the default project, `viewer.ts:258`) and that pages poll every 2 seconds (the project page polls every 3).

### Goals

- **The viewer matches the approved design** on every designed screen, in light and dark, following the system setting.
- **Live means live**: thumbnails, scores, inspector panes and comments update without a manual reload.
- **Every control is a real control**: tabs, menus, dialogs and row actions work by keyboard and touch.
- **The design stays the source of truth**: the viewer's tokens are the design system's tokens, and a test fails when they drift.

### User stories

- **US1**: As a reviewer, the gallery shows each canvas as a real thumbnail with its score on the corner, quiet when the canvas is at the bar and amber when it is below, and I can search by name and filter by Web, Mobile or Desktop app.
- **US2**: As a reviewer, a canvas's detail page shows the score, a one-line reason, the categories lowest first and the issues grouped, and "Show 4 nodes" outlines those nodes in the preview.
- **US3**: As a reviewer, when my agent resolves a comment or edits the canvas, the Feedback tab, the scores and the preview update while I watch.
- **US4**: As a reviewer, archiving and deleting live in a More menu, and deleting asks in a dialog that says it cannot be undone.
- **US5**: As a reviewer, the archive lists archived canvases by project, shows a preview of the one I select, and restores it to its project in one click.
- **US6**: As a reviewer on a light-mode OS, the viewer is light; on a dark-mode OS, dark.

## 5. ANALYZE  (risks and checks)

- **Selector tests break by design.** Ten unit tests and two browser tests assert markup strings (§3 names them per slice). Each slice rewrites the ones its page touches, and its PR lists every assertion it changed and the behaviour that assertion still covers, so coverage moves rather than drops.
- **Gallery cost.** Cards gain a type label, a states count and a below-the-bar summary, all from data the page already loads (`listCanvases` rows and the cached fast evaluation, `evalFor`, `viewer.ts:909`). No new per-card evaluation is added; `test-viewer-perf.ts` guards it.
- **Polling cost.** FR-B4 compares `versionHash`, which `listCanvases` computes for every canvas on each call (the Phase 30 perf finding). `/api/canvases` already does this every 3 seconds today, so the cost is unchanged.
- **Fonts offline.** FR-A3's fallback keeps the viewer usable with no network and an empty cache; the acceptance images are taken with the cache warm.
- **Design drift.** The canvases can be edited later. FR-A2's test pins only the tokens; layout drift between the canvases and the code is caught by FR-E4 at the end of this phase, not continuously.
- **Found, out of scope: CORS on mutating routes.** Every viewer response sets `Access-Control-Allow-Origin: *` (`viewer.ts:85`), including `POST` archive and feedback and `DELETE` canvas. The server binds `127.0.0.1`, but a page the user visits can still send a simple cross-origin `POST` to it. This needs its own change and its own test, separate from a visual port.
