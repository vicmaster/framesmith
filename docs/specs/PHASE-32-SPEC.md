## 1. SPECIFY

### Problem

Phases 30 and 31 closed with seven follow-ups recorded, not fixed. Five of them are quiet false passes, where `canvas_evaluate` says READY on something that is wrong (the disabled instance, the misspelt token, the boundary and indicator gaps, and the two phone gaps); one is a visual defect (the tints) and one a stress gap. Reproduced on master, the first six fall into five problems:

1. **Instances are invisible.** `resolveVariables` (`src/variables.ts`, `deepResolve`) recurses into `children` only, and an `instance` has none, so a component's subtree is never resolved and `applyControlDefaults` never runs on it. The renderer expands instances after resolution (`src/renderer.ts:607`, `resolveInstance` at `:680`), so a `disabled` button inside an instance renders at full opacity in the fallback `#2563EB`, not the design system's color. The evaluator's contrast, spacing and cliché checks read `buildTreeContext(resolvedRoot)` (`src/evaluate.ts:2540`) without expanding instances at all: text at 1.14:1 inside an instance raises nothing, while the same text outside is an error. Some checks do expand instances (the mobile and desktop-app rules, the state checks and the 24px census through `expandForRules`, `evaluate.ts:2431`; the icon and coverage checks through `expandInstances`, `src/drift.ts:265`), but they read it unresolved, with two different id schemes.
2. **Misspelt tokens are silent.** An unresolved `$ref` stays a raw string (`lookupToken`, `variables.ts:427-449`), and the renderer drops or emits it invalid: `gap: "$space-xxs"` is ignored (`renderer.ts:773`), and `padding`, `cornerRadius`, `width`, `rowGap`, `shadow`, `fill` and `stroke` behave the same. Canvases with three such typos scored 98 and 99 with no finding. The token-usage stat (`evaluate.ts:735`) counts each typo as token use. A related crash: `content: "$body"` resolves to the number 16 and crashes the renderer (`renderer.ts:1456`), because `deepResolve` resolves every top-level string, copy included.
3. **Seeded tints survive a light preset.** `applyStructure` seeds every color token a scaffold references from `DEFAULT_SCAFFOLD_COLORS` (`src/structures.ts:1856-1876`, seeding at `:2157-2164`). The tint seeds are dark washes (`accent-tint #152A47`, `success-tint #0F2E1B` and three more). No preset defines a tint, so `apply_preset light` leaves them: a `status-chip` renders a dark pill on a light page. Phase 31 slice D stopped seeding `accent-tint` for desktop primitives only (`structures.ts:1938-1944`); web scaffolds still seed it. `danger` (`#F87171`) survives the same way, because the light preset defines `error`, not `danger`, and primitives read `danger ?? error`.
4. **Two checks skip what they should measure.** `desktop-app-boundary` measures `text-input`, checkbox, radio and toggle only (`boundaryPairs`, `src/state-checks.ts:268`), and `select` draws its border in `$border`, not `$border-strong` (`variables.ts`, the select branch): 1.46:1 on white under a generated system, unflagged. `desktop-app-state-contrast` measures `nav-item` and line `tabs` only (`indicatorPairs`, `state-checks.ts:211-236`), because `tree-row` draws no indicator mark when active (`renderTreeRow`, `renderer.ts:1610`). Phase 31 recorded both as decisions (PHASE-31-SPEC R4 and R7); this phase reverses them.
5. **Phone canvases skip three primitives and two overlays.** The 44px census (`checkUsability` touch branch, `evaluate.ts:2155-2165`) loops `TAPPABLE_PRIMITIVES` (`src/primitives.ts:24`: button, list-row, tab-bar, nav-bar) and the four controls. `link` and `text-input` are not in it, and on a touch canvas the 24px pointer census is skipped too (`evaluate.ts:2660`), so a 24px link on a phone passes. A `modal`'s close button and actions are 32px and a `toast`'s action 24px (`overlayTargets`, `primitives.ts:122-133`), measured on web and desktop-app but never on a phone. PHASE-31-SPEC slice B's as-built note E2 says the new primitives "join the phone tappables"; the code does not, and `test-desktop-primitives.ts:142-143` pins that they do not.

One is a stress gap: `nav-item.count` and `tabs.items[].count` are not stress slots (`PRIMITIVE_TEXT_PROPS`, `src/stress.ts:45-68`), and `propSlots` collects string values only, so a numeric count would be skipped even if listed. Measured once in Chrome at 240px, a `999+` count on a `nav-item` narrows the label from 201 to 185px; the effect on `tabs` depends on the tab count, and slice D measures it.

And one is housekeeping the follow-ups will land in. 140 tests and `test-env.ts` sit loose in the repo root (141 of its files). The tier is a text match (`CHROME_MARKERS`, `scripts/run-tests.ts:49`) plus two exception lists, and 33 files the runner calls Node-only import a module that can launch Chrome, so the tier is a guess. Tests are never type-checked: `tsconfig.json` includes `src/**` only and `tsx` does not check types. A strict check over the root tests finds 54 errors in 21 files.

### Goals

- **Tests in folders that set their tier**, type-checked, with the tier proved at run time instead of guessed from text.
- **One tree**: what the renderer draws inside an instance is what every rule judges.
- **Every `$ref` accounted for**: a token that does not exist, or is the wrong kind, is a finding with a fix.
- **Tints that follow the theme**, on new stamps and on canvases already stamped.
- **The state checks measure every boundary and indicator they claim to.**
- **Stress exercises counts.**
- **Every tappable thing on a phone is measured at 44px**, with a way for overlays to meet it.

### User stories

- **US1**: As the maintainer, `npm run test:fast` runs `test/unit` and fails any unit test that launches Chrome, naming the folder it belongs in.
- **US2**: As the authoring agent, a disabled button inside a component instance renders dimmed, and a low-contrast text inside one is an error naming the instance.
- **US3**: As the authoring agent, `gap: "$space-mdd"` is a warning that `canvas_autofix` renames to `$space-md`, and `gap: "$space-xxs"`, which is close to three tokens, is a warning that names them.
- **US4**: As the authoring agent, `apply_structure("kpi-card")` then `apply_preset light` gives light tint chips, and a canvas stamped before this phase does too.
- **US5**: As the authoring agent, a `select` whose border is 1.46:1 warns, and an active `tree-row` shows a bar the indicator check measures.
- **US6**: As the authoring agent, a 40px `text-input`, a 24px `link` or a default `modal` on a phone canvas is a 44px error, and `size: "lg"` or `controlSize: "md"` clears it.

## 2. CLARIFY  (forks: decisions)

- **C1: How far the instance fix goes.** *Decided (Victor, 2026-11-19):* one tree for render and every rule (FR-B1), not a render-only fix. A render-only fix would dim the disabled button but leave contrast and spacing blind inside every component, which is the same false pass one level down.
- **C2: Active indicators.** *Decided (Victor, 2026-11-19):* `tree-row` gets `nav-item`'s bar and joins the check; contained tabs keep the filled segment and are documented as unmeasured (FR-D2, FR-D3). A bar inside a pill is a visual change to every contained tablist for a cue the fill and weight already give.
- **C3: Canvases stamped with the old seeds.** *Decided (Victor, 2026-11-19):* an exact seed value counts as unset on read (FR-C6). It fixes every stored canvas without rewriting files; the cost is that a user who typed one of the six exact seed values by hand gets the derived or inherited value instead.
- **C4: Where e2e runs.** *Decided (Victor, 2026-11-19):* the full tier only. Five e2e tests need no Chrome and leave the local fast loop. CI still runs every test, but its browser job runs on Node 24 only (the fast job runs 22 and 24), so those five lose their Node 22 run; that is accepted, since every unit test still runs on both. Splitting e2e by Chrome would keep the text marker this slice deletes.
- **C5: The `test-` prefix.** *Decided (no problem to solve, 2026-11-20):* keep it (`test/unit/test-cliche.ts`). Dropping it was cosmetic: tiering, the guard and the type check work either way, and it would add a rename to all 140 files, on top of the move, while breaking every closed spec's by-name reference. The prefix also keeps a test recognisable outside its folder.
- **C6: Interactive tests.** *Decided (follows from FR-A2):* a `test/manual` folder the runner never reads, replacing the `INTERACTIVE` list. The slice's rule is that the folder sets the tier; any other home for the two interactive tests would need an exception list again.
- **C7: Overlay control size naming.** *Decided (Victor, 2026-11-20):* `controlSize` with `button`'s size names on both overlays. `size` already means width on `modal`, and the names an agent knows from `button` mean the same heights here. A `touch: true` boolean was rejected: it names a device instead of a size and cannot express a height between 24 and 44.
- **C8: `unknown-token` severity.** *Decided (precedent):* warning, in the structure category, the same as the unknown-icon finding (`src/evaluate.ts:871`), which is the same failure for icons: a name that resolves to nothing. A warning blocks presenting, which a typo must, since it always renders something other than intended.
- **C9: The Phase 31 decisions reversed here.** *Decided (evidence):* R4 (no `tree-row` indicator) and R7 (`select` outside the boundary check) were scope calls, not findings that `select` and `tree-row` are fine. The 1.46:1 `select` reproduction shows the cost, and neither follow-up can be fixed without reversing them. The slice D PR notes both as superseded.

## 5. ANALYZE  (risks and checks)

- **Slice A is a large diff with no behavior change.** About 140 renames and every import line. The PR reviews by the file list (old path, new path, folder, why) and the unchanged count; `git log --follow` keeps history. A branch open during slice A would conflict on every moved file; no PR is open on 2026-11-19.
